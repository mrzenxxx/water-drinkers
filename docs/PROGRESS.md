## Решения, принятые по ходу

Сюда записывается только то, чего нет в `SPEC.md`, — выбор библиотеки,
обход ограничения, компромисс. Каждая запись: решение и почему.

### Расчёт

- **Даты — строки `YYYY-MM-DD`, арифметика без объекта `Date`.** Ни часовых поясов,
  ни скрытых часов; функции ядра остаются доказуемо чистыми.
- **Промежуточное произведение `сумма × дни` считается в `BigInt`.** Точность не
  зависит от масштаба сумм. `Math.round` в денежных расчётах не используется нигде.
- **Пересекающиеся отсутствия сливаются перед вычитанием.** База их запрещает (§11),
  но ядро не должно уметь вычесть один день дважды даже на грязных данных.
- **Вырожденный случай §4.4 разрешается цепочкой:** активные на дату заказа →
  задевшие период → все известные участники → ошибка, если участников нет вовсе.
- **`ADJUSTMENT` без участника распределяется поровну** между активными на дату
  операции. Подтверждено владельцем 14.08.2026, правило описано в `SPEC.md` §2.4.

### Аутентификация

- **Сессия — подписанная cookie без таблицы в базе.** В §11 таблицы сессий нет,
  и для полутора десятков человек она не нужна. Плата: отозвать одну сессию
  нельзя, отзывается весь набор — сменой `SESSION_SECRET`.
- **Отпечаток кода — HMAC-SHA256 на серверном секрете, не «быстрый» хеш.**
  Шестизначный код это миллион вариантов: SHA-256 без секрета перебирается по
  украденной базе за секунды. bcrypt не нужен — секрет в базе не лежит.
- **Ответ на запрос кода одинаков для любого адреса.** Различимый ответ превратил
  бы форму входа в справочник «кто скидывается на воду».
- **У `login_codes` добавлены `created_at` и индекс.** Выводить часовой лимит из
  `expires_at` можно, но он молча поедет при смене времени жизни кода.
- **Ошибки доступа бросаются как `GraphQLError`.** Обычный `Error` Yoga маскирует
  под `INTERNAL_SERVER_ERROR`, и клиент не отличает «войди заново» от «сервер упал».
  Поймано только живым запросом — ни типы, ни модульные тесты этого не видят.

### Фронтенд

- **Формы — на `useActionState` и `<form action>`, без `useEffect`.** Шаг входа
  выводится из состояния, а не хранится отдельно: два источника правды разъезжаются.
  Переход после успешного входа делает само действие. Правило — в `CLAUDE.md`.

### Инфраструктура

- **ESLint зафиксирован на 9.39.5:** `eslint-plugin-react` из состава
  `eslint-config-next@16.3.0` падает на ESLint 10.
- **Prisma 7 требует driver adapter** — добавлен `@prisma/adapter-pg`, конфигурация
  в `prisma.config.ts`. Клиент генерируется в `src/generated/prisma` и в git не
  попадает; его восстанавливает `postinstall`.
- **Клиент Prisma создаётся лениво, через прокси.** `next build` обходит модули
  маршрутов, и клиент, создаваемый на импорте, требовал бы базу во время сборки.
- **У `login_codes` добавлен суррогатный `id BIGSERIAL`** — в §11 первичного ключа
  не было, а Prisma требует уникальный идентификатор у каждой модели.
- **`EXCLUDE USING gist`, CHECK-ограничения и расширения `citext`/`btree_gist`**
  вынесены в написанную руками миграцию `prisma/migrations/00000000000000_init/`.
- **В codegen добавлены мапперы на модели Prisma.** Без них резолвер обязан вернуть
  сразу весь граф вместо строки таблицы.
- **Мутации-заглушки бросают `NOT_IMPLEMENTED`**, а не возвращают выдуманные
  сущности: заглушка, притворяющаяся рабочей, дороже в отладке.
- **Тесты ядра лежат в `tests/`, а не рядом с исходниками**, поэтому в
  `vitest.config.ts` добавлен отдельный шаблон включения.
- **`.claude/worktrees/` игнорируется git и ESLint:** рабочие копии субагентов —
  полные клоны проекта со своими сборками, линтер на них захлёбывался.
